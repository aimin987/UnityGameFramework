## 简介
本文档系统性地介绍Unity游戏框架提供的19个内置模块，重点详述其中最常用的七个核心模块：资源管理、实体系统、UI系统、场景管理、网络通信、事件系统和调试器。每个模块的介绍均包含概念性概述、具体功能说明、代码组织方式、模块间协作关系以及典型使用示例。同时，文档也会简要提及Config、DataNode、DataTable、Localization等其他重要模块的功能，以保持内容的全面性。

## 资源管理模块

资源管理模块（ResourceComponent）是游戏框架的核心基础，负责所有资源的加载、卸载、版本管理和内存策略。该模块强制采用异步加载机制，确保游戏运行的流畅性。

### 概念性概述
资源管理模块提供了一套完整的资源生命周期管理方案，支持单机模式和可更新模式。在可更新模式下，模块能够检查版本差异、下载更新资源并应用资源包，实现热更新功能。模块通过对象池技术管理资源实例，有效控制内存使用。

### 具体功能
- **强制异步加载**：所有资源加载操作均为异步，避免阻塞主线程
- **版本管理**：支持多版本资源列表的序列化与反序列化，实现版本控制
- **资源更新**：提供完整的资源更新流程，包括检查、下载、应用等环节
- **内存策略**：通过对象池管理资源实例，设置自动释放间隔、容量和过期时间

### 代码组织
在`Runtime/Resource`目录下，代码组织清晰：
- `ResourceComponent.cs`：核心组件类，提供外部API
- `BuiltinVersionListSerializer.cs`：版本列表序列化器，处理不同版本格式
- `DefaultResourceHelper.cs`：默认资源辅助器，实现具体加载逻辑
- 各类事件类（如`ResourceApplySuccessEventArgs`）用于事件通知

### 模块协作
资源管理模块是其他模块的基础依赖。UI系统、实体系统和场景管理模块在加载内容时都依赖于资源管理模块提供的异步加载功能。

### 使用示例
```csharp
// 异步加载资源
GameEntry.Resource.LoadAsset("Assets/UI/MainMenu.prefab", 
    new LoadAssetCallbacks(
        (assetName, asset, duration, userData) => {
            // 加载成功回调
            GameObject uiObject = (GameObject)asset;
            Instantiate(uiObject);
        },
        (assetName, errorMessage, duration, userData) => {
            // 加载失败回调
            Log.Error($"加载失败: {errorMessage}");
        }
    )
);
```

## 实体系统模块

实体系统模块（EntityComponent）负责游戏世界中所有动态对象的创建、管理和生命周期控制。

### 概念性概述
实体系统采用组件化设计，将游戏对象（实体）与其行为逻辑（EntityLogic）分离。系统通过实体组（EntityGroup）对实体进行分类管理，并利用对象池技术实现实体的高效复用。

### 具体功能
- **实体创建**：通过`ShowEntity`方法异步创建实体，支持指定实体编号、资源路径和所属组
- **显示与隐藏**：提供`ShowEntity`和`HideEntity`方法控制实体的可见性
- **挂接机制**：支持将一个实体挂接到另一个实体上，形成父子关系
- **对象池复用**：通过实体组的对象池管理实体实例，减少内存分配和GC压力

### 代码组织
在`Runtime/Entity`目录下：
- `EntityComponent.cs`：核心组件类，提供外部API
- `EntityComponent.EntityGroup.cs`：实体组定义，包含组配置参数
- `DefaultEntityHelper.cs`：默认实体辅助器，处理实体实例化
- `EntityLogic.cs`：实体逻辑基类，用户自定义逻辑继承此类

### 模块协作
实体系统依赖资源管理模块加载实体资源，并通过事件系统广播实体创建和销毁事件，与其他系统进行通信。

### 使用示例
```csharp
// 创建实体
int entityId = 1001;
GameEntry.Entity.ShowEntity<MyEntityLogic>(
    entityId,
    "Assets/Entities/Player.prefab",
    "PlayerGroup"
);

// 隐藏实体
GameEntry.Entity.HideEntity(entityId);

// 实体挂接
GameEntry.Entity.AttachEntity(childEntityId, parentEntityId);
```

## UI系统模块

UI系统模块（UIComponent）提供了一套完整的用户界面管理方案，支持界面的打开、关闭、层级管理和界面组功能。

### 概念性概述
UI系统将界面视为特殊类型的实体进行管理，支持按组组织界面，每个界面组具有独立的深度值，用于控制渲染顺序。系统通过序列编号唯一标识每个界面实例，并提供暂停被覆盖界面的功能。

### 具体功能
- **界面打开**：通过`OpenUIForm`方法异步加载并显示界面
- **界面关闭**：通过`CloseUIForm`方法关闭指定界面
- **层级管理**：通过界面组的深度值控制界面的渲染顺序
- **界面组功能**：支持创建多个界面组，如HUD组、弹窗组、背景组等

### 代码组织
在`Runtime/UI`目录下：
- `UIComponent.cs`：核心组件类，提供外部API
- `UIComponent.UIGroup.cs`：界面组定义，包含组名称和深度
- `DefaultUIFormHelper.cs`：默认界面辅助器，处理界面实例化
- `UIForm.cs`：界面基类，用户自定义界面继承此类

### 模块协作
UI系统依赖资源管理模块加载界面资源，通过事件系统广播界面打开和关闭事件，并可能通过网络模块获取远程数据。

### 使用示例
```csharp
// 打开界面
int serialId = GameEntry.UI.OpenUIForm(
    "Assets/UI/MainMenu.prefab",
    "UIGroup",
    true, // 暂停被覆盖的界面
    userData
);

// 关闭界面
GameEntry.UI.CloseUIForm(serialId);

// 激活界面（重新聚焦）
GameEntry.UI.RefocusUIForm(uiForm);
```

## 场景管理模块

场景管理模块（SceneComponent）负责游戏场景的加载、卸载和切换管理。

### 概念性概述
场景管理模块提供异步场景加载功能，支持加载过程中的进度更新和依赖资源加载事件。模块维护场景加载顺序，确保正确的场景激活状态，并自动管理主摄像机引用。

### 具体功能
- **场景加载**：通过`LoadScene`方法异步加载场景，支持优先级设置
- **场景卸载**：通过`UnloadScene`方法卸载指定场景
- **场景顺序**：通过`SetSceneOrder`方法设置场景加载顺序，控制场景激活优先级
- **主摄像机管理**：自动刷新当前场景的主摄像机引用

### 代码组织
在`Runtime/Scene`目录下：
- `SceneComponent.cs`：核心组件类，提供外部API
- 各类事件类（如`LoadSceneSuccessEventArgs`）用于场景加载状态通知
- `SceneAsset.cs`：场景资源相关定义

### 模块协作
场景管理模块依赖资源管理模块加载场景资源，并通过事件系统广播场景加载和卸载事件，通知其他系统进行相应处理。

### 使用示例
```csharp
// 加载场景
GameEntry.Scene.LoadScene("Assets/Scenes/GameScene.unity", 
    new LoadSceneCallbacks(
        (sceneAssetName, duration, userData) => {
            Log.Info($"场景加载成功: {sceneAssetName}");
        },
        (sceneAssetName, errorMessage, duration, userData) => {
            Log.Error($"场景加载失败: {errorMessage}");
        },
        (sceneAssetName, progress, duration, userData) => {
            Log.Info($"加载进度: {progress:P}");
        }
    )
);

// 设置场景顺序
GameEntry.Scene.SetSceneOrder("Assets/Scenes/GameScene.unity", 100);

// 刷新主摄像机
GameEntry.Scene.RefreshMainCamera();
```

## 网络通信模块

网络通信模块（NetworkComponent）提供了一套灵活的网络通信框架，支持多种网络协议和通信模式。

### 概念性概述
网络模块采用频道（NetworkChannel）设计，允许创建多个独立的网络连接，每个频道可以使用不同的网络服务类型（如TCP、UDP）。模块提供连接、断开、心跳检测、错误处理等完整的网络事件通知机制。

### 具体功能
- **网络频道管理**：支持创建、获取和销毁网络频道
- **连接管理**：提供连接建立、断开和错误处理功能
- **心跳检测**：自动检测网络连接的心跳状态
- **事件通知**：通过事件系统广播网络状态变化

### 代码组织
在`Runtime/Network`目录下：
- `NetworkComponent.cs`：核心组件类，提供外部API
- 各类事件类（如`NetworkConnectedEventArgs`）用于网络状态通知
- `NetworkClosedEventArgs.cs`：网络断开事件定义

### 模块协作
网络模块通过事件系统与其他模块通信，当网络状态变化时，会触发相应的事件，由事件系统广播给所有订阅者。

### 使用示例
```csharp
// 创建网络频道
INetworkChannel channel = GameEntry.Network.CreateNetworkChannel(
    "MainChannel",
    ServiceType.Tcp,
    new DefaultNetworkChannelHelper()
);

// 连接服务器
channel.Connect("127.0.0.1", 8888);

// 订阅网络事件
GameEntry.Event.Subscribe(NetworkEventCode.NetworkConnected, OnNetworkConnected);
GameEntry.Event.Subscribe(NetworkEventCode.NetworkClosed, OnNetworkClosed);

// 发送数据
channel.Send(packet);
```

## 事件系统模块

事件系统模块（EventComponent）提供了一套线程安全的事件通信机制，实现模块间的松耦合通信。

### 概念性概述
事件系统采用发布-订阅模式，允许任意模块订阅特定类型的事件，并在事件发生时收到通知。系统支持线程安全的事件抛出，确保即使在非主线程中触发事件，也能在主线程中安全回调。

### 具体功能
- **事件订阅**：通过`Subscribe`方法订阅特定事件类型
- **事件取消订阅**：通过`Unsubscribe`方法取消事件订阅
- **事件抛出**：通过`Fire`方法抛出事件，支持线程安全模式
- **默认处理器**：可设置默认事件处理器，处理未被特定订阅者处理的事件

### 代码组织
在`Runtime/Event`目录下：
- `EventComponent.cs`：核心组件类，提供外部API
- 无其他辅助类，功能集中

### 模块协作
事件系统是模块间通信的中枢，几乎所有模块都依赖事件系统进行通信。例如，资源加载完成、实体创建、UI打开等操作都会通过事件系统通知其他模块。

### 使用示例
```csharp
// 定义事件类
public class PlayerLevelUpEventArgs : GameEventArgs
{
    public static readonly int EventId = typeof(PlayerLevelUpEventArgs).GetHashCode();
    public override int Id => EventId;
    
    public int PlayerId { get; private set; }
    public int NewLevel { get; private set; }
    
    public static PlayerLevelUpEventArgs Create(int playerId, int newLevel)
    {
        PlayerLevelUpEventArgs eventArgs = ReferencePool.Acquire<PlayerLevelUpEventArgs>();
        eventArgs.PlayerId = playerId;
        eventArgs.NewLevel = newLevel;
        return eventArgs;
    }
}

// 订阅事件
GameEntry.Event.Subscribe(PlayerLevelUpEventArgs.EventId, OnPlayerLevelUp);

// 抛出事件
GameEntry.Event.Fire(this, PlayerLevelUpEventArgs.Create(playerId, newLevel));

// 事件处理函数
private void OnPlayerLevelUp(object sender, GameEventArgs e)
{
    PlayerLevelUpEventArgs args = (PlayerLevelUpEventArgs)e;
    Log.Info($"玩家{args.PlayerId}升级到{args.NewLevel}级");
}
```

## 调试器模块

调试器模块（DebuggerComponent）提供了一套强大的运行时调试工具，帮助开发者监控游戏状态和性能。

### 概念性概述
调试器模块包含多个功能窗口，如控制台、系统信息、性能分析、内存监控等。模块以漂浮窗口的形式显示，可随时打开或关闭，不影响游戏正常运行。

### 具体功能
- **控制台窗口**：实时显示游戏日志，支持按类型过滤
- **系统信息**：显示设备、操作系统、Unity版本等信息
- **性能监控**：显示FPS、内存使用、网络状态等性能指标
- **内存分析**：按资源类型（纹理、网格、材质等）统计内存占用
- **自定义窗口**：支持注册自定义调试窗口，扩展调试功能

### 代码组织
在`Runtime/Debugger`目录下：
- `DebuggerComponent.cs`：核心组件类，管理调试器窗口
- 多个`DebuggerComponent.*.cs`文件：各个调试窗口的具体实现
- `DebuggerActiveWindowType.cs`：调试器激活模式定义

### 模块协作
调试器模块依赖多个其他模块获取数据，如通过资源管理模块获取资源信息，通过对象池模块获取对象池状态，通过网络模块获取网络统计信息。

### 使用示例
```csharp
// 注册自定义调试窗口
GameEntry.Debugger.RegisterDebuggerWindow("Custom/MyWindow", new MyDebugWindow());

// 获取最近日志
List<LogNode> logs = new List<LogNode>();
GameEntry.Debugger.GetRecentLogs(logs, 10);

// 重置调试器布局
GameEntry.Debugger.ResetLayout();

// 控制调试器窗口状态
GameEntry.Debugger.ActiveWindow = true;
GameEntry.Debugger.ShowFullWindow = true;
```

## 其他核心模块

除了上述七个主要模块外，框架还提供了多个其他重要模块，共同构成完整的游戏开发解决方案。

### 配置模块（ConfigComponent）
负责管理游戏配置数据，支持从不同来源（如XML、JSON）加载配置，并提供便捷的访问接口。

### 数据节点模块（DataNodeComponent）
提供树形结构的数据存储和查询功能，适合管理层次化的游戏数据，如技能树、任务树等。

### 数据表模块（DataTableComponent）
用于管理游戏中的表格数据，如物品表、怪物表、技能表等，支持从CSV等格式导入数据。

### 本地化模块（LocalizationComponent）
支持多语言文本管理，可根据系统语言自动加载对应的本地化资源，实现游戏的国际化。

这些模块虽然使用频率相对较低，但在特定场景下发挥着重要作用，共同构成了完整的游戏框架功能体系。
