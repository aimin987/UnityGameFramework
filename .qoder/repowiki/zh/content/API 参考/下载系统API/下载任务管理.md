## 核心功能概述

`DownloadComponent` 是 Unity 游戏框架中的核心下载管理组件，负责封装下载任务的全生命周期管理。该组件提供了三大核心功能：通过 `AddDownload` 方法创建下载任务，通过 `RemoveDownload` 和 `RemoveAllDownloads` 方法移除任务，以及通过 `GetAllDownloadInfos` 方法查询所有任务状态。

该组件通过封装底层 `IDownloadManager` 接口，为上层应用提供了简洁、安全的 API。所有下载操作，如任务的添加、移除和状态查询，最终都委托给 `m_DownloadManager` 实例执行。同时，组件通过 `m_EventComponent` 将底层下载事件（如开始、更新、成功、失败）转发为游戏框架的事件系统事件，实现了功能解耦。

## 下载任务创建

`DownloadComponent` 提供了四个重载的 `AddDownload` 方法，用于灵活地创建下载任务。

### AddDownload 重载方法详解

#### 1. 基础重载：`AddDownload(string downloadPath, string downloadUri)`
这是最基础的创建方法，仅需指定下载路径和 URI。该方法会使用默认优先级（0）和空的用户数据。
- **downloadPath**: 指定文件下载完成后在本地存储的绝对路径。
- **downloadUri**: 指定文件的原始网络地址（URL）。

#### 2. 指定优先级：`AddDownload(string downloadPath, string downloadUri, int priority)`
此重载允许开发者为下载任务指定优先级。优先级数值越大，任务被调度执行的优先级越高。高优先级任务会优先被下载代理处理。

#### 3. 指定用户数据：`AddDownload(string downloadPath, string downloadUri, object userData)`
此重载允许附加一个用户自定义对象（`userData`）到下载任务。这个对象会在任务的整个生命周期中被传递，并在 `DownloadStartEventArgs`、`DownloadUpdateEventArgs` 等事件中被回调，用于关联业务逻辑。

#### 4. 完整参数：`AddDownload(string downloadPath, string downloadUri, int priority, object userData)`
这是功能最完整的重载，允许同时指定优先级和用户数据。

所有重载方法最终都会调用第四个重载，由 `m_DownloadManager.AddDownload` 执行实际的任务创建逻辑。

## 下载任务移除

`DownloadComponent` 提供了两种移除下载任务的机制。

### RemoveDownload
`RemoveDownload(int serialId)` 方法用于移除一个特定的下载任务。它接收一个任务的序列ID作为参数。当调用此方法时，如果任务正在下载，它将被立即中断；如果任务在等待队列中，则会被直接移除。此方法是精确控制单个任务生命周期的关键。

### RemoveAllDownloads
`RemoveAllDownloads()` 方法用于一次性移除所有当前存在的下载任务，包括正在下载和等待中的任务。这是一个批量操作，常用于场景切换或资源管理器重置时，以清理所有未完成的下载。

这两个方法都直接委托给 `m_DownloadManager` 的对应方法执行。

## 下载任务查询

`GetAllDownloadInfos()` 方法用于获取系统中所有下载任务的当前状态信息。它返回一个 `TaskInfo` 结构体数组，每个 `TaskInfo` 包含了单个任务的详细信息，如序列ID、下载路径、下载地址、已下载大小、总大小、下载速度等。

此方法对于实现下载进度监控界面至关重要。开发者可以定期调用此方法，遍历返回的数组，根据每个任务的 `CurrentLength` 和 `TotalLength` 计算出进度百分比，并实时更新UI。

## 任务序列ID的作用

任务序列ID（`serialId`）是 `DownloadComponent` 中一个至关重要的概念，它在下载任务的生命周期管理中扮演着核心角色。

### 唯一标识符
每个通过 `AddDownload` 创建的任务都会被分配一个全局唯一的整数序列ID。这个ID是区分不同下载任务的唯一凭证。

### 生命周期管理
序列ID是操作特定任务的“钥匙”。无论是查询任务状态、更新进度，还是取消任务，都必须通过这个ID来定位目标任务。例如，`RemoveDownload` 方法必须传入正确的 `serialId` 才能准确地移除指定任务。

### 事件关联
在下载过程中触发的 `DownloadStartEventArgs`、`DownloadUpdateEventArgs` 等事件中，都包含了 `SerialId` 字段。这使得上层逻辑能够将事件与具体的下载任务关联起来，从而执行针对性的业务处理。

### 底层调度
`IDownloadManager` 内部使用序列ID作为任务的索引，高效地管理任务队列和状态。它确保了任务的创建、调度、更新和销毁都能围绕这个唯一的ID进行，保证了系统的稳定性和一致性。

## 代码示例

以下代码示例展示了如何使用 `DownloadComponent` 的各项功能。

### 批量添加任务
```csharp
// 定义要下载的文件列表
string[] downloadUris = new string[] {
    "http://example.com/file1.zip",
    "http://example.com/file2.zip",
    "http://example.com/file3.zip"
};

// 批量创建下载任务，使用用户数据标记任务来源
for (int i = 0; i < downloadUris.Length; i++)
{
    string downloadPath = Path.Combine(Application.persistentDataPath, $"file{i+1}.zip");
    object userData = new { Source = "ContentPack", Index = i };
    int serialId = DownloadComponent.AddDownload(downloadPath, downloadUris[i], userData);
    Debug.Log($"任务 {serialId} 已创建，下载 {downloadUris[i]}");
}
```

### 根据ID取消特定任务
```csharp
// 假设已存储了某个重要任务的序列ID
int importantTaskId = 1001;

// 在需要时取消该任务
if (DownloadComponent.HasDownload(importantTaskId)) // 假设有此方法检查任务存在
{
    DownloadComponent.RemoveDownload(importantTaskId);
    Debug.Log($"任务 {importantTaskId} 已被取消。");
}
```

### 获取所有任务状态进行监控
```csharp
// 在 Update 或定时器中调用
TaskInfo[] allTasks = DownloadComponent.GetAllDownloadInfos();
float totalProgress = 0f;

foreach (TaskInfo task in allTasks)
{
    if (task.TotalLength > 0)
    {
        float taskProgress = (float)task.CurrentLength / task.TotalLength;
        totalProgress += taskProgress;
        Debug.Log($"任务 {task.SerialId}: {taskProgress:P2}");
    }
}

if (allTasks.Length > 0)
{
    totalProgress /= allTasks.Length; // 计算平均进度
    UpdateDownloadProgressBar(totalProgress);
}
```

## 底层调度机制

`DownloadComponent` 的功能实现依赖于 `IDownloadManager` 接口，这体现了清晰的分层设计思想。

### 接口委托模式
`DownloadComponent` 并不直接管理下载逻辑，而是通过其私有字段 `m_DownloadManager`（`IDownloadManager` 类型）来代理所有操作。在 `Awake` 方法中，它通过 `GameFrameworkEntry.GetModule<IDownloadManager>()` 从游戏框架的模块系统中获取 `IDownloadManager` 的具体实现。

### 事件驱动架构
`DownloadComponent` 在初始化时订阅了 `m_DownloadManager` 的多个事件（`DownloadStart`, `DownloadUpdate`, `DownloadSuccess`, `DownloadFailure`）。当底层下载状态发生变化时，`m_DownloadManager` 会触发这些事件。`DownloadComponent` 的事件处理函数（如 `OnDownloadStart`）会将这些原生事件包装成游戏框架的 `GameEventArgs`（如 `DownloadStartEventArgs`），并通过 `m_EventComponent` 的事件系统进行广播。这使得其他游戏组件可以方便地监听和响应下载事件，而无需直接依赖下载组件。

### 职责分离
这种设计实现了职责的完美分离：
- `IDownloadManager` 负责核心的下载调度、代理管理、网络请求等底层逻辑。
- `DownloadComponent` 负责提供易用的API、与Unity引擎集成（如创建下载代理的GameObject）、以及与游戏框架事件系统的桥接。

这种架构使得系统既灵活又易于维护和扩展。
